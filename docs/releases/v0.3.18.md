# AG Relay v0.3.18

## 修复：持续限流不再无限空转

**现象**：某些对话在 Claude Code 或 Codex 中会长时间停在“等待中”，最后才报 `rate_limit_exceeded`，有时一轮要等几分钟甚至反复重来，看起来像“无限 limit”。

**原因**：上游中转站会按请求里的缓存键（`prompt_cache_key`，用于复用旧对话的计算结果）把请求固定到某条通道。一旦这条通道的额度触顶，它就会持续返回 `rate_limit_exceeded`。旧版网关只会用完全相同的请求反复重发，重发多少次都打在同一个通道上，于是一直空转。

**修复**：同一请求连续两次收到明确的限流错误后，网关会**更换一次缓存键**，请求内容、对话历史、推理记录、工具结果和会话身份全部保持不变；新的缓存键若成功，会被记住并在后续请求中复用，避免每轮都重新预热。

- 仅对 Claude 和 Codex 生效；ZCode、未知客户端，以及没有携带缓存键的请求保持原有行为。
- Codex 原有的会话预清理（对已登记会话去掉旧推理和条目编号）仍先执行，换键不会绕过它。
- 不增加重试次数、不增加时间预算，已开始输出的内容不会被重放。
- 鉴权失败、额度耗尽、历史错误和其他网络故障不会触发换键。

## 实测效果

同一份卡住的旧对话请求：旧缓存键下 9.5 秒即被限流；换成新缓存键后 42.7 秒完整跑完。经修改后的网关处理还原的旧请求，4 次上游尝试、51.6 秒收到完成响应。

## 其他

- 诊断记录新增换键日志（不含缓存键原文），便于以后排查同类问题。
- 未改变连接设置、端口、上游地址或客户端配置，更新后需要重启网关生效。
