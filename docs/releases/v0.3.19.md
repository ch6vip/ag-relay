# AG Relay v0.3.19

## 变更：删除自动更换缓存键

v0.3.18 曾在同一请求连续两次明确限流后自动更换一次缓存键。经过进一步核对，这个做法缺乏足够依据：少量“换键后恢复”的现象也可能是限流额度自行恢复或上游负载变化；同时更换缓存键会让已有缓存无法复用，长对话需要重新处理大量输入。

**这一版起，网关不再自动换键。**客户端自己带上的缓存键原样转发，客户端没带也不会凭空添加。

## 限流时实际会发生什么

- 明确限流仍按原有次数和时间预算重试，不再修改请求内容。
- 等待时间、总重试预算、取消与“已输出内容不重放”的规则都没有改变。
- 需要你手动做的其他修复（历史兼容、会话绑定编号、账号绑定的旧推理不可用）保持原样，不会因为限流被触发。
- 已知的普通限流在高峰期本来就可能需要多次重试；换键删除后不承诺恢复更快，也不保证费用更低。

## 面板能看到什么

请求进展里新增“等待重试”阶段：清楚表明网关是在等待后再试，而不是上游正在生成内容。尝试次数仍然只统计已经真正发出的请求。

诊断里仍保留实际尝试次数、错误次数、限流类别、上游等待提示和最终结果，方便以后判断是否需要新的处理办法。

## 其他

- 依赖和许可材料已复核，组件集合未变。
- 未改变连接设置、端口、上游地址或客户端配置；更新后需要重启网关生效。
