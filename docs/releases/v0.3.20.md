# AG Relay v0.3.20

## 新增：Claude 和 Codex 的未覆盖错误保底

上游有时会换一种报错文案，旧网关没有对应的专用修复，只能直接返回错误或原样反复重试。这一版增加一次通用的历史兼容尝试，减少这类问题每次都要单独修网关的情况。

处理顺序是：

- 正常请求维持现状，不提前删除推理历史。
- 已认识的错误优先走原有专用处理。
- 遇到符合条件、尚未覆盖的错误，先原样再确认一次。
- 仍失败时，只生成一份去旧推理及适用编号的兼容请求，再实际尝试最多两次；次数和时间仍受原预算限制。

候选阶段即使变成限流、网络异常或其他错误，也不会重新获得两次机会；不会反复加码删除历史，不把本次剥离记成下次对话的默认处理。

## 两个客户端各用自己的安全处理

Claude 保留可验证的消息和工具历史，省略旧推理及适用编号。Codex 还会按现有规则配套处理搜索与推理的编号关联，但保留搜索内容和扩展信息。

两者都保留消息正文、工具参数和结果、配对用的 `call_id`、会话身份及客户端缓存键；不删除本地聊天记录，不关闭模型本轮思考。v0.3.19 删除的自动换键没有恢复。

## 默认与限制

- 两组的“未覆盖错误保底”默认开启，可在“重试与剥离”页单独移除/关闭；只有“报错后”历史模式参与，关闭历史处理或选择“提前处理”时不会重复叠加。
- 只对明确识别的 Claude/Codex Responses 请求生效，ZCode、未知或身份冲突的客户端不扩大处理。
- 明确限流、鉴权、余额、内容限制、模型/上下文限制以及普通服务/网络故障，不靠剥离解决。
- 服务端引用、未知或压缩历史、无法验证的工具配对以及没有可安全删除的内容，仍拒绝强行改写。
- 已开始交付真实内容或工具调用后不重放；取消和正常长流保护保留。

**这是一项有损的兼容尝试。**省略旧推理可能影响复杂任务的思路延续和缓存复用，不承诺所有新错误都能恢复、速度更快或费用更低。它的目标是在安全范围内多给未覆盖错误一次机会，而不是吞掉错误或把失败显示成成功。

## 诊断与设置兼容

沿用现有修复记录，说明是否尝试了保底、移除了多少项，以及为什么拒绝或停止；不增加新的统计看板或错误正文采集。

旧保存设置会补齐新选项，明确关闭的设置保持关闭；旧核心缺少该能力回执时，界面显示运行策略未核实，不冒充已经生效。
